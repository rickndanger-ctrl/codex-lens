# Milestone 4 — iPhone ↔ Gateway Contract

This is the blueprint the iOS side builds against. Every shape here is exactly
what `packages/gateway` returns today (see `src/routes/*.ts`,
`src/realtime/credentials.ts`, `src/events/event.ts`, `src/tasks/task.ts`).

## Principles

- **The long-lived OpenAI key never reaches the phone.** The phone authenticates
  to the *gateway* with a gateway bearer token, and the gateway mints a
  **short-lived** OpenAI Realtime credential for it. The phone opens its own
  Realtime connection with that short-lived credential.
- **The phone streams, it does not re-read.** Task progress is a per-task,
  strictly-increasing `seq`. The phone polls with the last `seq` it saw and
  only ever receives newer events.

## Authentication

Every endpoint except `GET /v1/health` requires:

```
Authorization: Bearer <CODEX_LENS_GATEWAY_TOKEN>
```

Missing/invalid → `401 { statusCode: 401, error: "Unauthorized", message }`.
This gateway token is provisioned onto the device out of band; it is **not** the
OpenAI key and grants only gateway access.

Base URL in development: `http://127.0.0.1:8787` (see `GATEWAY_HOST` /
`CODEX_LENS_PORT`), reached from the phone over the private network (Tailscale).

## 1. Short-lived Realtime credential

```
POST /v1/realtime/credentials
Authorization: Bearer <gateway token>
Content-Type: application/json

{ "model"?: string }          // optional; gateway default used when omitted
```

Unknown fields → `400`. (The request is strict; do not send `apiKey` or any
secret — the phone never holds one.)

### 200 — the ephemeral credential

```jsonc
{
  "value":     "ek_...",                    // short-lived client secret
  "expiresAt": "2026-07-16T12:00:00.000Z",  // ISO-8601, offset-aware
  "model":     "gpt-realtime",
  "sessionId": "sess_abc"                   // optional
}
```

- `value` is what the phone uses to open its OpenAI Realtime connection. Treat
  it as a secret at rest, but it is scoped and expiring by design.
- **Renew before `expiresAt`.** Conversation/task state must live outside the
  Realtime session so a credential renewal never loses the project.

### Errors

| status | when | body |
| --- | --- | --- |
| 400 | malformed request | `{ statusCode: 400, error: "Bad Request", message }` |
| 401 | missing/invalid gateway token | `{ statusCode: 401, error: "Unauthorized", message }` |
| 503 | issuer not configured, or upstream failed | `{ statusCode: 503, error: "Service Unavailable", message }` |

A `503` carries **no upstream detail** — the phone should surface "voice service
temporarily unavailable" and retry with backoff. It never means "bad token".

## 2. Tasks

A task is one Codex run against an allowlisted project. The phone creates one,
then streams its events.

```
POST /v1/tasks
{ "projectId": string, "idempotencyKey": string, "requestedPath"?: string }
```

Retrying with the same `idempotencyKey` returns the same task (safe to resend on
a flaky connection). `200` returns a task (`CodexTask` in the iOS client):

```jsonc
{
  "id":             "task_...",
  "projectId":      "sample-project",
  "state":          "queued",               // queued | running | complete | failed
  "idempotencyKey": "...",
  "createdAt":      "2026-07-16T...Z",
  "updatedAt":      "2026-07-16T...Z"
}
```

`GET /v1/tasks/:taskId` returns the same shape. Errors: `400` invalid,
`404 { statusCode: 404, error: "Not Found", message }` unknown task,
`422` unprocessable path.

## 3. Incremental event stream (the cursor contract)

```
GET /v1/tasks/:taskId/events?after=<seq>
Authorization: Bearer <gateway token>
```

`after` is optional, an integer `>= -1`. **Omit it (or pass -1) for the whole
log.** Malformed → `400`. Unknown task → `404`.

### 200

```jsonc
{
  "events": [
    {
      "id":        "evt_...",
      "taskId":    "task_...",
      "seq":       0,                        // per-task, starts at 0, strictly increasing
      "type":      "queued",                 // queued | running | log | complete | failed
      "payload":   { /* type-specific object */ },
      "createdAt": "2026-07-16T...Z"
    }
  ],
  "nextCursor": 4                            // pass as ?after= next poll
}
```

### The contract the phone MUST honor

1. Start with no cursor (or `after=-1`) to get the backlog.
2. Remember `nextCursor` from every response.
3. Poll `?after=<nextCursor>`; you receive **only** events with `seq > after`.
4. `nextCursor` is the highest `seq` returned, or the cursor you passed when
   nothing is new. **It never rewinds** — safe to persist across reconnects.
5. A terminal event (`complete` or `failed`) ends the stream; stop polling.

Typical run for the seeded sample project (2 commands):
`queued(0) → running(1) → log(2) → log(3) → complete(4)`.
